# 스마트스토어 상품 SEO (사과)

목표: 키워드를 정한 뒤(`naver-keyword-research`) 그 키워드로 **실제 검색 결과에 노출·클릭되도록**
상품 등록정보를 고친다. 수정안에는 항상 "무엇을, 왜(어떤 랭킹 요소 때문에)"를 함께 적는다.

최종 목적은 친구가 판매하는 **실제 사과의 주문·판매중량 증가**다. 검색 노출은 중간 지표이며,
할인·광고비·배송비·반품을 반영한 이익 악화를 함께 확인한다. 판매 저조의 원인은 점검 전에는 미확인이다.
상품 링크와 현재 품종·산지·중량·과수·흠과/정품·수확/저장 상태·재고를 먼저 확보한다.

## 0. 먼저 최신 가이드 확인

네이버 쇼핑 검색 랭킹 정책과 상품명 가이드는 바뀐다. 점검 전에 네이버 쇼핑 파트너센터 /
스마트스토어센터 공지의 **최신 "네이버쇼핑 검색 SEO 가이드"**를 확인하고, 아래 체크리스트와 다른
부분이 있으면 가이드를 따르고 이 파일을 갱신한다(갱신일을 하단에 기록).

공식 근거와 운영 가설을 구분한다. [네이버 비즈니스 스쿨](https://bizschool.naver.com/online/course/63827/lecture/1435945?currentTab=curriculum)은 카테고리·상품명·브랜드/제조사·속성·태그와 적합도를 안내하나 **가격비교 검색 교육**임을 명시한다.
가격비교·플러스스토어 추천·광고 영역을 구분하고 같은 알고리즘/순위라고 가정하지 않는다.
[가격비교 검색품질 FAQ4814](https://help.sell.smartstore.naver.com/faq/content.help?faqId=4814),
[플러스스토어 검색품질 FAQ15578](https://help.sell.smartstore.naver.com/faq/content.help?faqId=15578),
[공식 SEO 가이드 PDF](https://join.shopping.naver.com/misc/download/seo_guide.pdf)도 함께 확인한다.
플러스스토어는 개인 선호도와 굿서비스 기반 몰 신뢰도도 안내한다. 가격비교와 같은 고정 순위로 해석하지 않는다.
상품명 길이·태그 개수 등 세부 제한은 해당 공식 문서/현재 등록화면에서 확인한 경우에만 확정한다.

## 1. 랭킹 요소 프레임

| 요소 | 의미 | 판매자가 움직일 수 있는 것 |
| :--- | :--- | :--- |
| 적합도 | 검색어와 상품정보가 얼마나 맞는가 | 상품명, 카테고리, 속성(품종·산지·중량 등), 태그 |
| 인기도 | 클릭·판매실적·리뷰 등 공개 설명 범위에서 해석 | 클릭과 구매를 돕는 상품 제안 개선. 요소별 가중치·반영 기간은 추정하지 않는다 |
| 신뢰도 | 페널티·상품정보/SEO 가이드 준수 여부를 공식 도움말로 확인 | 정확한 정보와 가이드 준수. 판매자 등급을 확정 순위 요소로 단정하지 않는다 |

## 2. 감사 체크리스트

**상품명**
- [ ] 핵심 구매형 키워드(예: 품종 + 산지 + 중량 + 용도)가 앞쪽에 있다
- [ ] 같은 단어 반복 없음, 특수문자·이모지 남용 없음, 홍보 문구(`최저가`, `무료배송`, `특가`) 없음
- [ ] 타 브랜드명·관련 없는 인기 키워드 없음
- [ ] 너무 길지 않다(가이드 권장 길이 이내) — 키워드를 다 넣으려 하지 말고 나머지는 속성·태그로
- [ ] 실제 상품과 일치(중량·과수·등급) — 불일치는 반품·리뷰 악화로 인기도까지 떨어뜨린다

**카테고리·속성**
- [ ] 실제 상품에 맞는 최하위 카테고리다(공식 분류 기준 우선, 경쟁 상품은 참고)
- [ ] 품종·산지·중량·원산지 등 속성 필드를 빠짐없이 채웠다(필터 검색 노출에 영향)

**태그**
- [ ] 상품명에 못 넣은 미들·롱테일 키워드를 태그로 보완했다
- [ ] 태그사전에 없는 태그, 상품과 무관한 태그는 쓰지 않는다

**이미지·상세페이지·가격**
- [ ] 대표 이미지가 실제 사과의 크기·구성·포장과 일치하고 모바일 썸네일에서도 식별된다(CTR 개선 가설, 인기도와 동일한 값은 아님)
- [ ] 상세페이지 첫 화면에 품종·실중량·과수/크기 범위·흠과 기준·배송일·교환 안내가 이해하기 쉽게 보인다
- [ ] 산지·수확일·당도 등 주장은 증빙 가능한 사실만 쓴다. 상세페이지 개선은 구매 결정 지원이며 검색 순위 상승을 보장하지 않는다
- [ ] 같은 품종·등급·크기·중량·포장·배송 조건의 상품과 실결제금액 및 kg당 가격을 비교했다(옵션 추가금·배송비·쿠폰 조건 포함)
- [ ] 옵션명/기본 표시가격에 혼동이 없고 재고·출고 가능일이 실제 운영과 맞는다
- [ ] 공개 리뷰/문의에서 파손·멍·크기·맛·배송 불만과 구매 전 질문을 확인하고 대응안을 작성했다(평점·리뷰 조작 금지)

## 2-1. 가공품(사과즙 등) 추가 점검 — #75, 2026-10-28

- [ ] 용량×포수·총용량이 상품명·옵션·상세·라벨에서 같다. 팩당·100ml당 가격은 같은 포수·용량끼리만 비교한다
- [ ] 제조일·소비기한·유효일과 출고 마감 시각이 상품정보·상세·배송 안내에서 서로 맞다. 1/1·12/31 같은 기본값이 남아 있으면 실제 로트 라벨로 정정한다(효과 시험 대상 아님)
- [ ] 제조원·판매원·브랜드 필드가 실제 라벨과 같다. 광고 카탈로그의 브랜드/제조사 미입력도 확인한다
- [ ] 포장 표기·상품명에 쓰는 단어가 다른 산지·업체 상표와 겹치지 않는지 키워드 도구·검색 결과로 확인한다(예: 얼음골=밀양 얼음골사과, 사과하나=타 업체 결합 검색어)
- [ ] 산지 단독 검색어(예: 청송사과)는 가공품 카테고리와 맞지 않아 광고 노출이 불가할 수 있다. 상품명 표현과 성과 측정 검색어(예: 청송사과즙)를 구분한다

## 3. 경쟁 상품 비교 절차

1. 목표 키워드별로 쇼핑 검색 API 상위 N개(기본 40개, 1페이지) 수집: `title`, `lprice`, `mallName`, `category1-4`, `productType`.
2. 상위 상품명 토큰화 → 토큰 등장 빈도표. 상위권에 공통인데 우리 상품명에 없는 토큰 = 적합도 갭 후보.
3. 같은 중량 기준 kg당 가격 분포에서 우리 위치 확인.
   상품명에 10kg가 있어도 카드 속성/표시가격은 3kg·5kg 옵션일 수 있다. 실제 선택 옵션·배송비·과수·등급을 검증하기 전에는 kg당 가격이나 고가/저가 결론에 사용하지 않는다. API 사용이 불가능하면 현재 공개 UI 카드로 범위를 명시해 조사한다.
4. API 결과는 `API 조회 범위 내 확인 안 됨`으로 기록한다. 실제 화면은 검색어·영역·정렬·기기·로그인 여부·시각·관찰 범위를 별도로 남긴다. 둘 모두 전체 미노출이나 보편적인 고정 순위라고 단정하지 않는다.

경쟁 상품명에 등장하는 토큰도 우리 상품의 실제 속성과 일치할 때만 후보로 쓴다. 광고 표식이 있는 결과와 자연검색을 분리한다.

## 4. 수정안 형식

| 항목 | 현재 | 제안 | 근거(랭킹 요소·데이터) | 기대 효과 측정 지표 |
| :--- | :--- | :--- | :--- | :--- |

- 한 번에 여러 항목을 바꾸면 효과를 분리할 수 없다 → 가능하면 **한 번에 한 요소씩** 바꾸고 날짜를 기록한다.
- 수정 날짜는 `search-demand-capture` 분석에서 이벤트(개입) 시점으로 쓰므로 반드시 남긴다.
- 각 제안에 `대상 상품ID·가설·수정 전/후·주문/이익 목표·관찰기간·중단/복구 조건`을 덧붙인다. 조회수만 오르고 주문이 늘지 않으면 성공으로 보고하지 않는다.
- 상품정보가 잘못된 경우는 즉시 수정안을 만들고, 효과 측정을 위해 오류를 유지하지 않는다. 여러 오류를 함께 고쳤다면 묶음 개선으로 기록한다.

## 5. 하지 말 것

- 상품명 키워드 도배, 잦은 상품명 변경(순위가 흔들릴 수 있다), 리뷰·구매 조작.
- 가이드 확인 없이 기억에 의존한 규칙(글자 수 등)을 확정 사실처럼 제안.
