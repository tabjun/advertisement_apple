# 검색 수요 포착 분석 (SEO 성과 측정)

README 분석 축 ④(Conversion)의 실행 절차다. 질문은 하나: **"사과 관심이 늘었을 때 우리가 그 수요를
흡수했는가, 놓쳤다면 언제·어떤 키워드에서인가?"** 결과는 `naver-keyword-research`(어떤 키워드)와
`smartstore-listing-seo`(무엇을 고칠지)의 다음 액션으로 되돌린다.

## 0. 판매 증가 요청의 시작점

이 프로젝트의 중심 스킬이다. 먼저 README와 process의 현재 맥락을 읽고, 특정 스토어·주력 상품 1~3개로 범위를 좁힌다.
스토어/상품 URL, 실제 상품 규격·재고·출고 역량, 최근 4~8주 일별 상품·유입경로별 방문/주문/판매수량/매출, 광고 여부를 확인한다.
자료가 일부만 있으면 공개 상품 점검부터 진행하고 내부지표가 필요한 결론은 미확인으로 남긴다. API 개발부터 시작하지 않는다.

- 주지표: 취소·반품을 제외한 순주문수와 판매수량/판매중량(kg). 주문·주문상품·상자·kg를 구분하며 서로 다른 포장을 단순 합산하지 않는다.
- 보조지표: 순매출, 신규/재구매 주문(구분 가능할 때), 자연검색 유입, CTR·CVR.
- 이익 가드레일: 순매출 − 매입/생산 원가 − 판매자 부담 포장/배송/수수료/할인 − 반품 손실 − 광고비. 순매출에 반영된 환불·할인은 다시 빼지 않는다. 판매자 수취 배송비도 정의에 포함하고 비용과 중복 처리하지 않는다. 원가 미확인이면 수익성 미확인으로 표시한다.
- 목표 증가량·관찰기간·재고/배송 제한은 기준선 확인 후 정한다. 판매 증가율이나 상위 노출을 보장하지 않는다.

사용자가 승인한 범위에서 자료 확인·수정안 작성·측정을 진행한다. 스킬 사용 자체는 라이브 상품 변경이나 광고비 지출의 승인이 아니다.

## 1. 데이터 정렬

| 계열 | 소스 | 단위 |
| :--- | :--- | :--- |
| 시장 수요 | 데이터랩 검색어트렌드/쇼핑인사이트 (키워드 그룹별) | 상대지수, 일별 |
| 시장 규모 참고 | 검색광고 키워드도구 월간 검색수 | 통합검색 범위·집계기간 확인. 일별 실제 쇼핑 수요로 변환하지 않는다 |
| 우리 노출·유입 | 스마트스토어 검색 리포트·유입 리포트(Excel) | 일별, 키워드별 |
| 우리 성과 | 판매 리포트(주문수·매출), 광고 리포트(노출·클릭·전환) | 일별 |
| 개입 기록 | 상품명/태그/가격 수정일, 광고 on/off, 프로모션 | 날짜 이벤트 |

- 모든 계열을 **같은 날짜 인덱스**로 맞추고 결측일은 0과 구분해 표시한다(리포트 미다운로드 ≠ 유입 0).
- 오가닉 유입과 광고 유입은 반드시 분리한다. 섞으면 SEO 효과를 판정할 수 없다.
- 실제 리포트에 있는 열만 사용한다. 자연검색 노출/클릭이 없으면 CTR은 계산 불가다. 광고 CTR을 대신 쓰지 않는다. 날짜는 한국 시간으로 통일하고 결제일·주문일·환불 반영 기준, 광고 기여기간·전환 지연을 기록한다.
- 시장지수와 우리 성과는 키워드군·기간·기기/성별 등 조건이 맞는지 확인한다. 검색어트렌드와 쇼핑 클릭지수는 다른 모집단이며 합치거나 동일한 분모로 쓰지 않는다.
- 구매자 이름·연락처·주소는 분석에 필요 없다. 상품/날짜/채널 수준 집계로 작업한다.

## 2. 지표

- **상대 수요 대응지수** = `(현재 평균 일유입 / 기준 평균 일유입) / (현재 평균 시장지수 / 기준 평균 시장지수) × 100`. 같은 정규화 요청·범위의 시계열에서만 비교한다. 분모가 0이거나 기준 유입이 없으면 계산 불가로 표시한다. 이것은 시장점유율·실제 포착률이 아니다. 데이터랩은 상대지수라는 [공식 정의](https://developers.naver.com/docs/serviceapi/datalab/search/search.md)에 따른다.
- **변화율 비교**: 시장 수요보다 우리 유입이 덜 늘면 점검 후보다. 상품 불일치·경쟁·재고·측정 범위·노출/클릭 단계를 확인하기 전에는 놓친 매출이나 SEO 실패로 확정하지 않는다.
- **키워드별 갭**: 시장에서 뜨는 키워드 그룹(예: 추석 선물세트) 중 우리 유입 키워드 목록에 없는 것.
- **퍼널**: 노출 → 클릭/방문 → 주문 → 순주문/이익. CTR은 같은 범위의 클릭/노출, CVR은 주문/방문 또는 전환/클릭 중 실제 사용한 정의를 명시한다. 데이터 범위가 다르면 비율을 만들지 않는다.
  - 노출 부족: 상품이 판매/노출 가능한 상태인지, 쇼핑 연동·재고·카테고리·제재/심사·수요·경쟁·검색어 적합성을 차례로 확인. 원인을 상품명으로 단정하지 않는다.
  - 노출 대비 클릭 부족: 썸네일·실결제가격·배송 조건·리뷰와 타깃 키워드의 적합성 점검.
  - 방문 대비 주문 부족: 실제 구성·크기·흠과 기준의 명확성, 가격·옵션·배송·품질 증빙·리뷰 불만 점검.
  - 주문 증가에도 이익 감소: 할인·광고·배송비·반품·상품 믹스를 점검. 방문 증가를 성과로 대체하지 않는다.

## 3. 개입 효과 판정

1. 주력 상품과 가장 큰 병목을 정하고 `가설 | 변경 전/후 | 주지표 | 기준기간 | 관찰기간 | 예산 한도(광고 시) | 유지/중단/복구 조건`을 작성한다. 2주 전후 비교는 시작점이며 판매가 적으면 기간보다 누적 방문·주문과 불확실성을 보고 판단한다.
2. 요일·명절까지 남은 날·품종 시즌·시장지수·가격·재고·출고 중단을 함께 비교한다. 변화율 차이는 참고 통계이며 인과효과가 아니다. 가능하면 비슷한 미변경 상품/기간을 비교하되 조건 차이도 밝힌다.
3. 같은 기간 다른 개입(광고·프로모션)이 겹쳤으면 "분리 불가"로 명시한다.
4. 데이터가 쌓이면 개입 전 시장지수로 우리 유입을 예측하는 단순 모형(회귀·인과영향 분석)을 고려하되, **Excel 1차 분석으로 필요성이 확인된 뒤에만**(README 원칙).
5. 0→1건 증가에 개선율을 계산하거나 적은 표본의 CTR·CVR 변화로 승패를 확정하지 않는다. 건수·분모·기간을 같이 보고하고 자료가 부족하면 판단 유보/추가 관찰로 남긴다. 주문 증가의 관찰 결과와 해당 변경의 인과효과를 구분한다.

## 4. 오가닉 vs 광고 판단 규칙

- 단기 수요 피크라도 재고·명절 배송 마감·주문당 이익과 현재 전환 상태가 맞을 때만 제한된 광고 실험을 검토한다. 자동 집행하지 않는다.
- 놓친 수요가 **상시/장기 시즌**이면 → 상품명·속성·태그 수정으로 오가닉 확보가 우선.
- 광고 키워드는 `naver-keyword-research` 우선순위표에서 구매형·롱테일부터, 빅키워드는 CPC 대비 전환 확인 후.
- 광고 상품별 타기팅 방식을 확인한다. 키워드도구 후보를 쇼핑검색광고의 직접 입찰 키워드 목록으로 간주하지 않는다.
- 주문당 광고 전 기여이익이 확보되면 허용 CPA는 그 이익에서 필요한 잔여 이익을 뺀 값으로, 허용 CPC는 허용 CPA × 동일 광고 범위의 예상 CVR로 산출한다. CVR 미확인이면 시나리오로만 표시하고 수치 예산·손실 한도를 정하기 전 집행하지 않는다. 광고 귀속 매출과 스토어 전체 증분 매출은 구분한다.

## 5. 산출물

- 일별 정렬 테이블(시장 수요·우리 유입·주문·개입 플래그)과 갭 키워드 목록 → `result/`(gitignore).
- 결론(놓친 구간·원인 단계·다음 액션) 요약 → `history.md`, 다음 Step → `process.md`.
- 실행안은 최우선 1~3개로 좁혀 `대상 상품 | 확인한 사실/가설 | 수정안 | 측정 지표 | 관찰기간 | 담당자 | 유지/중단 조건`을 남긴다. 보고서는 순주문·판매kg·이익 결과를 먼저, 노출·방문 변화는 이유 설명에 사용한다.
